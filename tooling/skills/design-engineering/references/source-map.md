# Design-engineering source map

Use these as seed sources, then verify the current page, tool, price, license,
account requirement, and compatibility before relying on it. Prefer primary
documentation for technical or licensing claims.

## Broad discovery

- [Design Engineer Tools](https://designengineer.tools/) — category discovery;
  never treat inclusion as Fleet endorsement.
- [DesEngs](https://desengs.com/) — recently curated design-engineering
  resources across reading, watching, using, building, learning, and community;
  use it to discover primary sources, not as evidence that a resource is
  suitable or endorsed.

## Inspiration

- [60fps](https://60fps.design/) — interaction and motion references.
- [Godly](https://godly.website/) — expressive web references.
- [Mobbin](https://mobbin.com/) — product-flow and interface references.
- [Game UI Database](https://www.gameuidatabase.com/) — game and spatial UI
  references.

Use broad sources to discover candidates. Cite the original product page when
it is available rather than citing only the gallery.

## Components

- [The Component Gallery](https://component.gallery/) — cross-system component
  anatomy and implementation discovery.
- [shadcn/ui](https://ui.shadcn.com/) — inspect source-visible web patterns.
- [Motion Primitives](https://motion-primitives.com/) — motion-led component
  patterns.
- [React Bits](https://reactbits.dev/) — expressive component candidates.

Check semantics, state coverage, source license, package weight, and framework
compatibility independently. A polished demo is not proof of production
fitness.

## Evidence interfaces

- [Vercel design.md](https://vercel.com/design.md) — a detailed first-party
  report-design workflow; adapt its reader, evidence, and decision discipline,
  not its brand shell, assets, CSS API, tokens, or house style.

Verify factual and accessibility guidance independently when applying it to a
different product. The owning project's content and design authority remain
the contract.

## Web 3D

- [Blender](https://www.blender.org/) — authoring and offline processing.
- [gltfpack](https://github.com/zeux/meshoptimizer/tree/master/gltf) — glTF
  optimization candidate.
- [gltfjsx](https://github.com/pmndrs/gltfjsx) — React-oriented glTF conversion
  candidate.
- [Needle Viewer](https://viewer.needle.tools/) — glTF inspection candidate.

Prefer glTF/GLB for browser delivery when it fits the owning stack. Verify
asset provenance and optimization results rather than trusting file extension
alone.

## Creative effects

- [Easing Functions](https://easings.net/) and
  [Easing Editor](https://animejs.com/documentation/web-animation-api/tools/easing-editor/) —
  timing exploration.
- [ShaderToy](https://www.shadertoy.com/) and [cables](https://cables.gl/) —
  shader and node-based visual references.
- [Theatre.js](https://www.theatrejs.com/), [Rive](https://rive.app/), and
  [Lottie](https://lottiefiles.com/) — animation-authoring candidates.

Treat reference code and assets as separately licensed material. Recreate the
principle in project-native code unless reuse is clearly permitted and useful.
